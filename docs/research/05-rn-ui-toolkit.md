# React Native / Expo SDK 57 UI toolkit facts

On Expo SDK 57 (RN 0.86.3, React 19.2.3, still the latest stable; SDK 58 is beta only) a polished UI can be built entirely inside Expo Go: Expo Go 57.0.9 is back on the App Store (since 2 Sep 2026, needs the same Expo account logged in on CLI and phone), and it bundles Reanimated 4.5.1 + Worklets 0.10.1, Gesture Handler ~2.32, Skia 2.6.2, react-native-svg 15.15.4, @expo/ui, expo-glass-effect, expo-symbols, expo-blur, expo-haptics, expo-font and expo-video. For styling, the lowest-risk choice is plain StyleSheet plus a typed token module and RN's built-in boxShadow / experimental_backgroundImage gradients: Unistyles 3 does not run in Expo Go, NativeWind v5 is still a release candidate (v4.2.7 on Tailwind 3 is the stable line), and iOS `filter` only supports brightness/opacity. Motion should come from Reanimated 4 CSS transitions/keyframes and worklets; variable fonts are NOT supported until SDK 58, so ship static font files loaded with useFonts. Native tabs (still `expo-router/unstable-native-tabs` in SDK 57), link previews, Apple zoom transitions (alpha) and Liquid Glass are available but are iOS-version-gated or unstable, so none should sit on the demo-critical path. For the 40-node knowledge map both Skia and SVG are comfortably within Reanimated's performance guidance; SVG/Views give per-node taps and accessibility for free while Skia needs overlay views for hit-testing. The repo's apps/mobile is currently the blank template (no expo-router, no `experiments`, userInterfaceStyle "light"), so React Compiler and typed routes that the default SDK 57 template enables must be turned on by hand.

## Recommendations

- **must**: Stay on Expo SDK 57 + Expo Go for the demo and add every native library with `npx expo install` (Reanimated 4.5.1, Worklets 0.10.1, Gesture Handler ~2.32, react-native-svg 15.15.4, Skia 2.6.2 if used). Do not move to SDK 58 beta and do not adopt Gesture Handler 3.x or Skia 2.14 yet. Run `npx expo login` with the same account that is signed in to Expo Go on the phone. _Why:_ Expo Go only contains the pinned native binaries; npm 'latest' for gesture-handler (3.3.0) and Skia (2.14.0) is ahead of them and would mismatch. SDK 58's Expo Go is not available on physical iPhones, and local Xcode 26.0 cannot build SDK 56+ (needs 26.4). The login rule since 3 Sep 2026 is the most likely first-run failure on a real iPhone.
- **must**: Use plain `StyleSheet.create` plus one typed TypeScript token module (color, space, radius, type scale, motion durations) and RN 0.86 built-ins (`boxShadow`, `experimental_backgroundImage: 'linear-gradient(#0B1220, #13213D)'`) as the styling system. Do not add NativeWind, Unistyles, Tamagui or StyleX for this demo; if Tailwind is later wanted, use NativeWind 4.2.7 (not the v5 RC) or free Uniwind. _Why:_ Zero runtime and zero config, works in Expo Go, and the same token file can feed the reel renderer so app and reels share one theme. Unistyles 3 is excluded by Expo Go; NativeWind v5 is 'not intended for production use'; v4 pins Tailwind 3; a single dark theme with ~40 components does not need a styling engine, and React Compiler removes most of the memoization argument for one.
- **must**: Bring apps/mobile up to the default-template baseline: install expo-router, then in app.json set `experiments: { reactCompiler: true, typedRoutes: true }` and change `userInterfaceStyle` from "light" to "dark" (the reels and palette are dark-only). Write Reanimated code with `sv.get()` / `sv.set()` rather than `.value` from the start. _Why:_ The repo is on the blank template with none of these set; the official SDK 57 template enables both experiments. Typed routes catch broken hrefs for the 'tap a gap -> focused session' deep link, and the compiler-safe shared-value accessors avoid a later rewrite.
- **should**: Build the knowledge map as a hybrid of React Native Views for nodes/cells and one react-native-svg layer underneath for PREREQUISITE_OF / RELATED_TO edges. Each of the 40 concept cells is a `Pressable` + `Animated.View` whose `backgroundColor`/`transform` change through Reanimated CSS transitions when mastery state changes; a keyframe `animationName` pulse marks 'due for review'. Reach for Skia only if a glow/blur look is required that views cannot produce on iOS. _Why:_ Tapping a gap and VoiceOver labels come free with Views/SVG, whereas Skia needs mirrored overlay views for per-node hit-testing. 40 animated views is well under Reanimated's 100 (low-end Android) / 500 (iOS) guideline, backgroundColor/transform are the cheap non-layout props, and the 'map visibly fills in' beat becomes a state change with a declared transition instead of imperative animation code. RN `filter: blur` does not exist on iOS, which is the one case that would justify Skia.
- **should**: Ship static font files (3-4 weights of one OFL family, e.g. via an @expo-google-fonts package) loaded with `useFonts` behind the splash screen, or use the system font (SF Pro / Roboto, with iOS `ui-rounded` / `ui-monospace` for accents). Do not use a variable font on SDK 57. Set `maxFontSizeMultiplier` (about 1.3-1.5) on text overlaid on reels and on the map, and `fontVariant: ['tabular-nums']` on counters and timers. _Why:_ Variable fonts are only supported from SDK 58; config-plugin embedding does not work in Expo Go; dynamic type is on by default and will break fixed overlays on a 720x1280 video if unbounded. Choosing the same OFL family for the reel re-render (about 1 hour, no API cost) unifies app and reel typography and satisfies the plan's 'OFL families only' rule.
- **should**: Drive the feed's gestures with Gesture Handler 2.32's `Gesture.Pan()/Tap()/LongPress()` + `GestureDetector` and Reanimated worklets; use CSS transitions/keyframes for state-driven UI (reason chip, quick-action feedback, retrieval-card reveal). Keep Reanimated shared element transitions and the Expo Router Apple zoom transition off the demo-critical path. _Why:_ These are the versions inside Expo Go. Shared element transitions are 'not recommended for production use yet' and zoom transition is alpha, iOS 18+ only, with a documented ~1 s delay, which would undercut a 3-minute live demo.
- **should**: Use an Expo Router `formSheet` route (`sheetAllowedDetents: [0.4, 1]`, `sheetGrabberVisible`) for 'why this reel' and for the focused-session launcher from the map; fall back to the @expo/ui universal `BottomSheet` only if a non-route sheet is needed. Skip @gorhom/bottom-sheet unless a fully custom gesture-driven sheet is required. _Why:_ formSheet is a native sheet with detents on both platforms, needs no extra dependency, and is routable (so 'tap a gap' is just a typed href). @expo/ui's sheet collapses custom snap points to half/full on Android. All three work in Expo Go.
- **should**: Use `expo-symbols` `SymbolView` with explicit `{ ios, android }` names behind one small `<Icon name=...>` wrapper, and add `expo-haptics` at the three learning beats: `selectionAsync()` when a reel snaps, `notificationAsync(Success | Error)` on a retrieval answer, `impactAsync(Light)` on quick actions. _Why:_ SF Symbols on iOS and Material Symbols on Android give native-quality icons with no font asset; the wrapper isolates a beta API and the iOS-only animation props. Haptics make the retrieval check feel consequential on a real phone, but must never carry meaning alone because iOS suppresses them in Low Power Mode.
- **could**: Treat Liquid Glass as progressive enhancement: wrap floating chrome (mode switch, reason chip, tab pill) in a `Surface` component that renders `GlassView` when `isLiquidGlassAvailable()` is true and otherwise a token-coloured translucent View (rgba of #13213D with a 1px border). Avoid `expo-blur` over the video on Android below 12, and never animate GlassView via opacity. _Why:_ GlassView exists only on iOS 26+ and silently becomes a plain View elsewhere, so the design must look finished without it. Android blur is only efficient on API 31+, and opacity 0 on a GlassView or its parent stops the glass from rendering.
- **could**: If a tab bar is wanted (Feed / Map), use `expo-router/unstable-native-tabs` with at most 3 tabs and plan the import rename for SDK 58; otherwise prefer a two-screen Stack with a custom floating pill built on the `Surface` component above. Decide after testing the feed's bottom overlay against the native bar on the actual phone. _Why:_ Native tabs give a system Liquid Glass bar on iOS 26 for free, but the API is still unstable in SDK 57 and the tab-bar height cannot be measured, which matters for a full-bleed video feed with captions and quick actions pinned near the bottom.

## Fact-check: changes to the recommendations

- MUST 'Stay on SDK 57 + Expo Go': keep, but add a time-bomb mitigation. SDK 58 stable is due about 6-13 Oct 2026 (beta began 15 Sep, 'three to four weeks'; expo@58.0.3 on the `next` tag 3 Oct). Shortly after, the App Store Expo Go updates to SDK 58 and 'drops SDK 57 support', which would stop the SDK 57 project opening on the demo iPhone. Do now: turn off App Store auto-updates on the demo phone and do not manually update Expo Go. Fallbacks, in order: (a) `npx eas-cli@latest go --sdk-version 57` to put an SDK 57 Expo Go on TestFlight (needs a paid Apple Developer account, no local Xcode); (b) an EAS development build; (c) upgrade the project to SDK 58 once stable (then re-verify every pin in this track). Decide which fallback applies before UI work starts.
- MUST 'npx expo install' rule: extend the reason to Reanimated (npm latest 4.7.1) and Worklets (latest 0.13.0); 4.5.1 requires worklets 0.10.x. Run it inside apps/mobile, then `npx expo-doctor`.
- MUST 'bring apps/mobile up to template baseline': the step list is incomplete. Per the Expo Router manual install: `npx expo install expo-router react-native-safe-area-context react-native-screens expo-linking expo-constants expo-status-bar`, change package.json `main` from 'index.ts' to 'expo-router/entry', add a `scheme` and the 'expo-router' plugin to app.json, move App.tsx content into src/app/_layout.tsx + routes (AGENTS.md mandates src/app/), start with `npx expo start --clear`. Also add expo-system-ui (Android ignores userInterfaceStyle in builds without it, and it sets the root background colour so a dark app does not flash white).
- SHOULD 'feed gestures with Gesture.Pan()': change. Do not hand-roll the vertical pager with a pan gesture. Use a native-scrolling pager (FlatList/FlashList with pagingEnabled + onViewableItemsChanged, or react-native-pager-view, all bundled in Expo Go) and keep Gesture Handler for tap / double-tap / long-press on the reel. Native paging gives correct momentum and rubber-banding for free and is the lower-risk path to the 3-minute demo. Give every reel its own VideoPlayer (Android cannot share one), preload the next player before it is attached, and set surfaceType='textureView' on Android if neighbouring VideoViews use contentFit 'cover'.
- SHOULD 'keep shared element transitions off the critical path': strengthen to 'not available'. Reanimated static feature flags cannot be changed in Expo Go, so shared element transitions do not exist there at all, and the performance-guide flags (synchronous UI props, commit-pausing) cannot be enabled. Do not design any screen transition (e.g. map cell -> focused session) around them; use plain Stack/formSheet transitions plus in-screen CSS transitions.
- SHOULD 'knowledge map as Views + SVG edge layer': keep. Add that animating the SVG edges themselves with CSS transitions is possible in Expo Go on 4.5.1 (flag default true) but only for Circle/Ellipse/Line/Path/Rect and is experimental, so make edge animation optional polish; node state changes on Animated.View remain the demo-critical 'map fills in' beat.
- SHOULD 'formSheet with sheetGrabberVisible': note the grabber is iOS-only; render a small token-styled grabber in the sheet content on Android, and keep to <= 3 detents there.
- MUST 'StyleSheet + token module with experimental_backgroundImage': keep, but wrap the gradient in one helper/token (e.g. tokens.gradient.reelBg) because the prop is documented unprefixed as `backgroundImage` from RN 0.87 onward; the SDK 58 upgrade should be a one-line change.
- COULD 'Surface with GlassView': guard with both isLiquidGlassAvailable() and isGlassEffectAPIAvailable(); unchanged otherwise.
- Correct the stated fact in the motion section: the Hermes V1 memory fix landed in expo@57.0.9 / RN 0.86.2; 57.0.17 / RN 0.86.3 fixed dev-mode startup time. No action needed (repo is on 57.0.26).

## Fact-check: what the track missed

- Expo Go store-version cutover: the single biggest schedule risk for an Expo Go demo on a physical iPhone. The App Store build will switch to SDK 58 and drop SDK 57 shortly after SDK 58 stable (expected mid-October 2026). The track said only 'do not move to SDK 58 beta'.
- `eas go` exists (`npx eas-cli@latest go`, --sdk-version flag, TestFlight delivery, requires $99/yr Apple Developer account). It is the documented way to keep a specific-SDK Expo Go on an iPhone without local Xcode; whether the user has a paid Apple Developer account is an open question that decides the fallback.
- Reanimated static feature flags are frozen in Expo Go (prebuilt defaults for 4.5.1: SVG CSS animations on, shared element transitions off, synchronous UI-prop updates off, USE_COMMIT_HOOK_ONLY_FOR_REACT_COMMITS on). Any design that depends on a non-default flag needs a dev build.
- Feed container choice was not researched: native paging list (FlatList/FlashList pagingEnabled or react-native-pager-view, all in Expo Go) versus custom pan gesture; plus expo-video feed specifics (one VideoPlayer per VideoView on Android, preload by creating the player before mounting, Android surfaceType 'textureView' for overlapping 'cover' videos, useVideoPlayer auto-release vs createVideoPlayer manual release()).
- Concrete Expo Router migration steps for this repo: main is 'index.ts' + App.tsx, no scheme, no plugins, npm-workspaces monorepo with hoisted expo/react-native; AGENTS.md requires routes under src/app/. Typed routes also need `npx expo customize tsconfig.json`.
- Android edge-to-edge: Expo docs state that with edge-to-edge you must use safe areas so content does not sit under system bars. A full-bleed video feed with bottom-pinned captions/quick actions needs react-native-safe-area-context insets (useSafeAreaInsets) on both platforms, plus expo-status-bar style 'light' for the dark theme. Not covered.
- Reduced motion: Reanimated animations default to ReduceMotion.System and useReducedMotion() exists; the accessibility guide does not say whether CSS transitions/keyframes honour the system setting. The 'due for review' pulse and 'map fills in' transitions need an explicit reduced-motion path (and the demo phone should have Reduce Motion off, or the key beat may not animate).
- lottie-react-native ^7.3.8 is compiled into the Expo Go app (apps/expo-go/package.json, sdk-57), an option for a one-off celebration/learned animation without Skia; not mentioned.
- Android was left unspecified: the login rule does not yet apply to Android, sheet grabber and custom @expo/ui snap points are iOS-only, blur/filter need Android 12+, glass is iOS 26+. If the demo is iPhone-only, say so and drop Android polish from scope; if Android is in scope these are the gaps.
- RN 0.87+ renames the gradient prop to `backgroundImage` and 0.87 deprecates ImageBackground ('use a View with an absolutely positioned Image'); relevant to how reel posters/thumbnails behind overlays are built so the SDK 58 upgrade is painless.

### 11. Reanimated 4.5.1 + Worklets 0.10.1 (New Architecture only, in Expo Go) support declarative CSS transitions (`transitionProperty`/`transitionDuration`) and keyframe animations (`animationName`) on Animated components on iOS/Android/web, alongside worklet-driven shared values. Shared element transitions are experimental behind a feature flag. Guidance: animate non-layout props, and at most ~100 animated components on low-end Android / ~500 on iOS. The Hermes V1 memory regression that hit Reanimated/Worklets apps is fixed in expo >= 57.0.17 (RN 0.86.3), which our repo already uses. Gesture Handler in Expo Go is the 2.x builder API (`Gesture.Pan()`), not the 3.x hook API.

Compatibility table: RN 0.86 supported by Reanimated 4.4.x-4.8.x; 4.5.x pairs with worklets 0.10.x/0.11.x; 'Reanimated 4 works only with the React Native New Architecture'. CSS transitions doc: Android/iOS/Web supported; 'We discourage the use of `all` property as it can lead to performance issues'. Performance guide: 'you should animate no more than 100 components for low-end Android devices and no more than 500 components for iOS'; 'Animating non-layout properties (like transform, opacity or backgroundColor) is generally more performant'. ### 12. For the 40-node knowledge map both drawing options run in Expo Go and are far inside performance limits; the real differences are interaction and cost. Skia (2.6.2) takes Reanimated shared values directly as props on one canvas but has no per-shape touch handling (you overlay Animated Views for hit-testing) and adds ~6 MB (iOS) / ~4 MB (Android) to a standalone build. react-native-svg (15.15.4) elements are individually pressable and animate via `createAnimatedComponent` + shared values/useAnimatedProps, or CSS transitions (experimental, default-on from Reanimated 4.4).

Skia animations doc: 'There is no need for functions like createAnimatedComponent or useAnimatedProps; simply pass the Reanimated values directly as properties'; use Skia's `interpolateColors`, not Reanimated's. Skia gestures doc: to activate gestures for one canvas element, 'overlay an animated view on it, ensuring that the same transformations applied to the canvas element are mirrored'. Skia install doc: iOS +6 MB, Android +4 MB, web +2.9 MB; requires react-native >=0.79, react >=19. Reanimated Animating SVG guide: wrap components with createAnimatedComponent; Circle animates cx, cy, r; fill/stroke/opacity/strokeDasharray animate on all platforms; CSS animations/transitions for SVG are an 'experimental feature, enabled by default from Reanimated 4.4'. No published benchmark for this exact case was found; the performance judgement rests on Reanimated's 100/500 animated-component guideline.

Source: <https://wcandillon.github.io/react-native-skia/docs/animations/gestures> · confidence: medium · version-sensitive

### 13. ### 14. expo-blur (~57.0.3), expo-haptics (~57.0.3), expo-linear-gradient, expo-mesh-gradient and expo-video (~57.0.5) are all available in Expo Go. Android blur is stable since SDK 55 but requires wrapping the blurred content in `BlurTargetView` and is only efficient on Android 12+ (API 31). iOS haptics silently do nothing in Low Power Mode, when the Taptic Engine is disabled, or while camera/dictation is active; Android should use `performAndroidHapticsAsync`.

blur-view docs: platform tags include 'Included in Expo Go'; 'The blur can be achieved efficiently only by using the RenderNode Android API, which was introduced in Android SDK 31'; blur 'does not update when BlurView is rendered before dynamic content'. haptics docs: impact styles Light/Medium/Heavy/Rigid/Soft, notification Success/Warning/Error, selectionAsync; Taptic engine inactive when 'Low Power Mode is enabled'. expo-haptics, expo-blur, expo-video, expo-linear-gradient, expo-mesh-gradient appear as workspace deps of apps/expo-go/package.json on the sdk-57 branch (https://raw.githubusercontent.com/expo/expo/sdk-57/apps/expo-go/package.json); the haptics doc page itself does not carry the 'Included in Expo Go' tag. expo-video docs: 'Included in Expo Go'; Android cannot mount multiple VideoViews on one VideoPlayer.

Source: <https://docs.expo.dev/versions/v57.0.0/sdk/blur-view.md> · confidence: high · version-sensitive

## Open questions

- Which physical phone(s) will run the demo (iOS version, and is any Android device in scope)? Liquid Glass and GlassView need iOS 26+, zoom transition needs iOS 18+, and Android blur/filters need Android 12+.
- Does Tamagui 2.x run in Expo Go on SDK 57? Its docs do not say; it appears JS-only but this was not confirmed from a primary source.
- Will NativeWind v5 be promoted to `latest` before UI work starts? As of late September 2026 it was still RC with performance work pending; only relevant if Tailwind-style classes are wanted.
- No benchmark was found for react-native-svg vs Skia at 40 nodes / ~100 edges with animated state changes on RN 0.86; the recommendation rests on Reanimated's animated-component guideline and should be confirmed with a quick device test, especially if edges are animated (strokeDashoffset) at the same time as nodes.
- How does the native tabs Liquid Glass bar behave over a playing expo-video VideoView in Expo Go (legibility, overlap with bottom captions), given the tab bar height cannot be measured? Needs an on-device check.
- RN 0.87 docs list the gradient prop as 'backgroundImage / experimental_backgroundImage'; whether the unprefixed name is the stable form in RN 0.88 / SDK 58 was not settled, which affects how the gradient token should be written for a later upgrade.
- Reanimated CSS transitions on react-native-svg elements are flagged experimental (default-on from 4.4); stability on 4.5.1 in Expo Go was not verified. Using View-based nodes avoids the dependency.
